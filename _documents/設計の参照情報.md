## 2. 解析ライブラリ候補の比較

設計時は候補のみ調査した。Issue #3 で Syndication 10.0.13 を採用して依存を固定したが、
**実装では項目単位の保留と日時の厳格な検査ができないため使わず、2026-11-02 のユーザー決定で依存を外した（Issue #73）。
解析は XmlReader と LINQ to XML の自前実装。** 以下の比較と採用時の記録は、当時の履歴として残す。

| 候補 | 形式・ライセンスの確認結果 | 評価 |
| --- | --- | --- |
| System.ServiceModel.Syndication | Microsoft、MIT、RSS2.0／Atom1.0 | **推奨**。今回の範囲と一致 |
| CodeHollow.FeedReader | MIT、RSS0.91/0.92/1.0/2.0／Atom | 代替。RSS1が必要なら再評価 |
| XMLパーサーで独自実装 | .NETはMIT、形式対応は自前 | 非推奨。日時・拡張・不正入力の負担が大きい |

Syndication は `dotnet/runtime` の MIT 本文と NuGet のライセンス表示を確認。
v10.0.0 の `SyndicationFeed.Load` は Atom10FeedFormatter と Rss20FeedFormatter を選ぶ。
RSS1／JSONの自動対応と誤認しない。
NuGet の使用例のように URL を XmlReader へ直接渡すのではなく、制限付き取得と解析を分離する。
content:encoded、HTML、非標準日時の扱いは、ライブラリの存在だけでは保証しない。

FeedReader は公式 README・LICENSE・csproj と、バイト列／文字列からの読込 API を確認。
MITで形式は広いが、取得機能も持つため、採用する場合もネットワーク部分は使わない。
旧フレームワークを含むターゲットや更新状況は、採用版の依存・試験で評価する。
この調査では実フィードの比較実行・性能比較はしていない。
